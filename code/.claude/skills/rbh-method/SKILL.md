# Method ladder
Order of priority: CORRECT first, then cheapest in usage, then fastest, then easiest for AJ, then shortest to read. A wrong answer costs more usage than a right one.
1. Can I answer from what I already know? Then do not re-read and do not search.
2. Can chat do it in the cloud and send the file? Then no PC task. The PC is only for the live database or the PC itself.
3. Free first: built-in tools, files already in the repo, free web sources. A paid or new tool needs AJ's OK.
4. Smallest change: one file, one module, only the tests for what changed.
5. At most ONE paste for AJ, once, in its own code block.
6. If the first method is blocked, take the next cheapest correct one, say in one line what you chose and why, and keep going.
7. Anything not run is UNVERIFIED.
