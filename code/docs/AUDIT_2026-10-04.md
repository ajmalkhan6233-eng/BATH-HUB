# Audit 2026-10-04 (cloud session, scratch database with fake data)

How: the repo's own `scripts/bugcheck.js` (68 checks) run LIVE against a throwaway Postgres built from `scripts/dev/test_schema.sql`
(never the real shop), the full Jest suite, browser checks of the public site at phone size (390px), and screenshots of the owner app.
Result after fixes: Jest 104 suites / 1203 tests pass; bugcheck 60 pass, 1 not applicable here (log-file check), 6 skipped, 0 real failures.

Honest count: **8 real defects found, 6 fixed**. The code had already been through a heavy audit (68 automated checks), so a list of 50
would have been padding. Nothing was invented to reach a number.

## Fixed
1. FRESH-DATABASE START-UP RACE (10 errors, one root cause). On a new database, route modules ran ALTER TABLE before their own CREATE TABLE
   had finished: investor_loans (4 errors), shop_operations (2), admin_audit (2), daily_entry_sync (1), notify_due_soon (1). Columns were then
   missing until the next restart and some pages answered 500 on first use. Fix: `utils/pool.js` runs plain start-up queries one at a time, in order,
   for the first 20 s (`PG_BOOT_SERIAL_MS`, 0 = off). Fresh database now boots with 0 errors. Test: `tests/unit/pool_boot_order.test.js`.
2. Ledger sync `GET /api/daily-entry/sync/:date` and `/meta/:date` answered 500 on a bad date in the address. Now 400.
3. Ledger `GET /api/daily-entry/range` accepted impossible dates (2026-02-30). Now 400.
4. The new start-up switch could not be turned off with 0 (caught by its own test). Fixed before commit.
5. Public website: no favicon (404 on every visit). Added favicon and apple-touch icon.
6. Public website: 14 of 18 buttons were under 40px tall on a phone (language, scene, finish, form buttons). Now 44px minimum.

## Found, NOT fixed (need you)
7. `public/daily-entry-v2.html` (ported ledger) still says "First Choice Bathco" in its header and report titles; the rename was blocked by the safety check.
8. The ported ledger is not linked from the /owner menu, so nobody can reach it except by typing the address. Needs a menu entry in `public/bathco_complete.html`.
Also still open from before: public site loads Google Fonts from Google (slower, shares visitors' IPs, fails offline); the staff-loans total counts
repayments as loans (same flaw in BATHCO); the ledger's Cheques tab is local-only on purpose; real sample products replace the "SAMPLE DATA" banner.

## Not a bug, but good to know
- `npm run bugcheck` needs a Windows backup file; here it was run by hand against a database built from the dev schema.
- bugcheck check 63 reads the real server's log, so it cannot pass on a scratch copy.
- The brute-force lock (10 wrong logins / 15 min, per address) works: the check locked its own test login, as designed.
